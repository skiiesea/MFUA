# Vesper — персональный мессенджер

Личные и групповые чаты в реальном времени, друзья, профили с обложками, двухфакторная защита (TOTP), админ-панель и отдельная система логов. Тёмная тема по умолчанию, светлая тема, акцентные цвета, адаптивный интерфейс для ПК, планшета и телефона.

**Стек:** React 18, TypeScript, Vite, Tailwind CSS, Framer Motion, Lucide · Node.js, Express, Socket.IO · PostgreSQL, Prisma · Zod · Pino · Argon2id.

> **Windows:** пошаговая инструкция с решением типичных ошибок лежит в файле [`README-WINDOWS.md`](README-WINDOWS.md).

> **Важно о статусе проекта.** Код написан в среде без доступа к сети: зависимости не устанавливались, приложение **ни разу не запускалось** и не проверялось компилятором TypeScript против реальных библиотек. Что проверено: синтаксис всех 87 TypeScript-файлов, разрешение импортов, юнит-проверки криптографии (AES-GCM, подписанные тикеты 2FA), парольной политики, цветов и форматирования. Всё остальное (HTTP-маршруты, SQL, сокеты, интерфейс) нужно проверить при первом запуске. Ожидайте мелкие ошибки: см. раздел [«Первый запуск и отладка»](#первый-запуск-и-отладка).

## Быстрый старт

Требуется **Node.js 20+** (рекомендуется LTS 22: у самых новых версий Node иногда нет готовых сборок нативных пакетов `argon2` и `sharp`) и **PostgreSQL 14+** (проще всего через Docker).

```bash
# 1. Зависимости (устанавливает server и web через npm workspaces)
npm install

# 2. Проверка окружения: покажет, что именно не так, если что-то сломано
npm run doctor

# 3. PostgreSQL в Docker (или используйте свой, тогда поправьте DATABASE_URL)
docker compose up -d

# 4. Конфиг: создаёт server/.env и генерирует секреты APP_SECRET и ENCRYPTION_KEY
npm run setup

# 5. Миграции базы (при первом запуске создают папку server/prisma/migrations)
npm run db:init

# 6. Первый администратор (интерактивно, пароль вводится скрыто)
npm run create-admin

# 7. Запуск backend (:4000) и frontend (:5173) одной командой
npm run dev
```

Все команды работают в cmd, PowerShell (включая Windows PowerShell 5) и bash. `npm run doctor` можно запускать на любом шаге, в том числе при неудачной установке.

Откройте <http://localhost:5173>.

**Письма подтверждения в разработке.** Пока `SMTP_HOST` не задан, письма не отправляются, а печатаются в консоль сервера (блок `DEV MAIL`): скопируйте оттуда ссылку подтверждения. Для быстрой проверки можно поставить `REQUIRE_EMAIL_VERIFICATION=false` в `server/.env`.

## Настройка `.env`

Файл `server/.env` создаётся командой `npm run setup`. Все переменные описаны в `server/.env.example`. Главные:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения PostgreSQL |
| `CLIENT_URL` | публичный адрес приложения; используется в письмах и для проверки Origin (CSRF и WebSocket). Несколько адресов через запятую |
| `APP_SECRET` | ≥32 символов; подпись тикетов 2FA и хеши резервных кодов |
| `ENCRYPTION_KEY` | 32 случайных байта в base64; шифрование TOTP-секретов (AES-256-GCM) |
| `SMTP_*` | почта для подтверждения email. Без неё письма идут в консоль |
| `LOG_DIR` | папка логов, по умолчанию `../logs` (корень проекта) |
| `LOG_MAX_SIZE`, `LOG_MAX_FILES` | ротация: размер файла и число архивов |
| `UPLOAD_DIR`, `MAX_UPLOAD_MB` | хранилище файлов и лимит размера |
| `TRUST_PROXY` | `1`, если сервер стоит за nginx/Caddy (нужно для корректных IP и rate limiting) |
| `COOKIE_SECURE` | `true` в продакшене по HTTPS |

Секреты генерируются так (если не хотите `npm run setup`):

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"   # APP_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"      # ENCRYPTION_KEY
```

**Потеря `ENCRYPTION_KEY` делает невозможным вход пользователям с 2FA.** Храните его в резервной копии отдельно от базы.

## PostgreSQL

Через Docker (`docker-compose.yml` в корне):

```bash
docker compose up -d      # старт, порт 127.0.0.1:5432
docker compose down       # стоп (данные сохраняются в volume)
```

Значения по умолчанию (`vesper` / `vesper_dev_password` / база `vesper`) подходят только для разработки. Для продакшена задайте свой пароль и обновите `DATABASE_URL`.

## Миграции

```bash
npm run db:init       # первая миграция «init» (разработка)
npm run db:migrate    # новые миграции после изменения schema.prisma (спросит имя)
npm run db:deploy     # продакшен: применяет готовые миграции
npm exec -w server prisma studio   # просмотр данных в браузере
```

## Первый администратор

Роль хранится в БД (`User.role = ADMIN`), а не в клиенте. Единственный способ получить её: серверный CLI.

```bash
npm run create-admin
```

Скрипт спросит логин, имя, email и пароль (ввод скрыт, пароль проходит ту же политику и хешируется Argon2id). Если логин уже существует, предложит назначить этот аккаунт администратором. Действие пишется в `security.log`. Затем войдите на сайте: в левой панели появится раздел «Админ». Все `/api/admin/*` проверяют роль на сервере при каждом запросе.

## Что реализовано

**Аккаунты и безопасность**
- Регистрация: уникальные логин и email, проверка сложности пароля, подтверждение email по ссылке (токен хранится как SHA-256, живёт 24 часа).
- Вход по логину или email, «запомнить меня», серверные сессии в БД (в cookie только случайный токен, в БД его хеш). Cookie `HttpOnly`, `SameSite=Lax`, `Secure` в продакшене.
- Пароли: Argon2id. Защита от перебора: rate limiting по IP + блокировка аккаунта на 15 минут после 5 неудач, выравнивание времени ответа для несуществующих логинов, одинаковое сообщение об ошибке.
- 2FA (TOTP): QR-код, проверка 6-значного кода, защита от повторного использования кода, 10 резервных кодов (хранятся хешами, одноразовые, регенерация), обязательная проверка при входе. Секрет шифруется AES-256-GCM. Включение, отключение и регенерация требуют пароль и код.
- Активные устройства, завершение отдельных сеансов или всех остальных (сокеты закрываются сразу), история входов (50 записей), смена пароля (завершает остальные сеансы), смена email с подтверждением нового адреса.
- CSRF: Origin + обязательный заголовок `X-Requested-With` + SameSite. WebSocket: проверка cookie-сессии и Origin (защита от CSWSH). Helmet + CSP. Лимиты на размер JSON и файлов.

**Профиль и люди**
- Уникальный ID и username, имя, статус, «о себе», дата регистрации, индикатор «в сети», время последней активности с настройками приватности.
- Аватар и широкая обложка: загрузка, кадрирование в браузере, предпросмотр профиля до сохранения, замена и удаление. На сервере изображения перекодируются через `sharp` (проверка содержимого, удаление метаданных).
- Поиск по username и имени, страница пользователя (`/@username`), заявки (входящие, исходящие, принять, отклонить, отменить), удаление из друзей, чёрный список, жалобы.

**Сообщения**
- Realtime через WebSocket: отправка, получение, typing, доставка и прочтение (галочки), непрочитанные счётчики, ответы, редактирование, удаление, реакции, закрепление, поиск по переписке с переходом к сообщению, разделители по датам, эмодзи, ссылки и @упоминания, оптимистичная отправка с повтором при ошибке.
- Вложения: изображения (с лайтбоксом) и файлы. Тип проверяется по расширению и по содержимому (magic bytes / sharp), размер ограничен. Файлы лежат вне публичной папки и отдаются только участникам чата с `nosniff` и `CSP: sandbox`.
- Группы: создание, название, описание, аватар, добавление и удаление участников (только друзья), роли владельца и администратора, выход из группы (владелец передаётся автоматически).

**Уведомления и настройки**
- Панель уведомлений: заявки, принятие заявки, упоминания, события безопасности. Звук (3 мелодии, громкость), отключение категорий (кроме безопасности).
- Настройки: аккаунт, безопасность, приватность (кто пишет, кто шлёт заявки, кто видит онлайн, последнюю активность и профиль), интерфейс (тема, акцентный цвет, масштаб).
- Из ваших дополнений: ссылки на профили `/@username`, кастомизация профиля (акцентный цвет страницы, фон шапки), статусы «Не беспокоить», «Не в сети», «На работе», «Свободен».

**Админ-панель** (`/admin`): статистика, список пользователей с поиском, блокировка и разблокировка (сеансы завершаются), жалобы, просмотр логов с фильтром по файлу, уровню и тексту.

**Логи** (папка `logs/`, доступ `0700`, просмотр только через админ-API): `application`, `auth`, `security`, `errors`, `access`. JSON-строки с `time`, `level` (DEBUG/INFO/WARN/ERROR), `event`, `userId`, `ip`. Ротация по размеру с gzip-архивами. Пароли, токены, секреты 2FA, резервные коды и тексты сообщений не пишутся: есть автоматическая цензура (`redact`), в access-логе нет query-строки, а при неизвестном логине не сохраняется введённая строка.

## Что не реализовано или имеет ограничения

- **Восстановление пароля по email** отсутствует (если забыли пароль, сбросить его может только администратор БД).
- **Redis не используется.** Онлайн-статусы и лимиты сокетов хранятся в памяти процесса, поэтому сейчас работает **один экземпляр** сервера. Для горизонтального масштабирования понадобятся Redis adapter для Socket.IO и общее хранилище presence.
- Уведомление о новом сообщении не сохраняется в БД: приходит в реальном времени (тост и звук), а непрочитанные видны по счётчикам чатов.
- Сообщения хранятся в БД открытым текстом (сквозного шифрования нет). Доступ к чужим перепискам закрыт проверкой членства на сервере, админ-панель переписки не показывает.
- Нет: звонков, пересылки сообщений, отключения звука отдельных чатов, push-уведомлений при закрытой вкладке, удаления аккаунта, антивирусной проверки файлов, автотестов API (есть только юнит-проверки отдельных функций).
- Поиск по сообщениям использует `ILIKE`; на больших объёмах добавьте индекс `pg_trgm`.
- Эмодзи-панель встроенная и компактная (без поиска).

## Первый запуск и отладка

1. **Сначала `npm run doctor`.** Он показывает, что сломано, и что делать.
2. **`Cannot find module ...\node_modules\tsx\dist\cli.mjs`** (или похожее про другой пакет): установка зависимостей прервалась или повреждена. Чистая переустановка (PowerShell):
   ```powershell
   Remove-Item -Recurse -Force node_modules, server\node_modules, web\node_modules -ErrorAction SilentlyContinue
   Remove-Item package-lock.json -ErrorAction SilentlyContinue
   npm install
   npm run doctor
   ```
   Если `npm install` выводит ошибки (чаще всего про `argon2`, `sharp` или `prisma`), поставьте Node 22 LTS и повторите. Папку проекта лучше держать вне OneDrive и не на «Рабочем столе» с синхронизацией, а антивирус может блокировать установку: добавьте папку проекта в исключения.
3. `npm run typecheck` покажет несоответствия типов. Dev-режим (`npm run dev`) типы не проверяет, поэтому сервер и Vite запустятся и при таких ошибках, а `npm run build` для web начинается с `tsc --noEmit`.
4. **`npm run db:init` завершился ошибкой.** Настоящая причина печатается *выше* строк `npm error Lifecycle script…`: ищите строку, начинающуюся с `Error:` или с кода вида `P1001`, `P1000`, `P1012`.
   - `P1012` или `Error validating`: ошибка в `schema.prisma`; проверьте `npm run db:validate`.
   - `P1001` (не удаётся достучаться до сервера БД): запустите Docker Desktop и `docker compose up -d`, проверьте `docker compose ps`.
   - `P1000` (ошибка аутентификации): пароль в `DATABASE_URL` не совпадает с `docker-compose.yml`; чаще всего порт 5432 занят уже установленным на Windows PostgreSQL. Тогда в `docker-compose.yml` замените `127.0.0.1:5432:5432` на `127.0.0.1:5433:5432`, в `DATABASE_URL` порт на `5433` и перезапустите контейнер.
5. Сервер не стартует с сообщением «Некорректная конфигурация (.env)»: он назвал, какая переменная неверна.
6. Не приходит письмо: смотрите консоль сервера (без SMTP письма печатаются туда).
7. Если после входа сразу выбрасывает на экран логина: открывайте приложение по тому же адресу, что указан в `CLIENT_URL`; в продакшене нужен HTTPS (cookie `Secure`).
8. Логи пишутся в `logs/*.log`, ошибки видны и в консоли. Для подробностей поставьте `LOG_LEVEL=debug`.

## Продакшен

```bash
npm run build
npm run db:deploy
npm start          # перед запуском задайте NODE_ENV=production (в PowerShell: $env:NODE_ENV="production")
```

- Поставьте перед сервером nginx или Caddy с HTTPS, задайте `TRUST_PROXY=1`, `CLIENT_URL=https://ваш-домен`. Проксируйте и WebSocket (`/socket.io`).
- Сервер сам раздаёт `web/dist` (см. `STATIC_DIR`) и SPA-маршруты.
- Настройте SMTP, смените пароль БД, делайте резервные копии БД, `uploads/` и `ENCRYPTION_KEY`.
